# Project documentation

## Purpose

Keep durable design decisions, verification commands, and meaningful change records discoverable.

## Ownership

- `PROJECT_MAP.md`: subsystem entry points and verification commands.
- `DECISIONS.md`: stable prompt, memory, migration and scheduling choices.
- `CHANGELOG.md`: what changed, why, touched files, behavior, limitations and follow-ups.

## Local Contracts

- Keep factual verification separate from model-quality judgments.
- Do not include private browser conversations or generated user data in committed records.

## Work Guidance

- Update the nearest source AGENTS.md for operational contracts; link to these docs for broader context.
- Keep setup and user instructions in the root README; keep this folder focused on subsystem maps, decisions and change records.
- Documentation-only changes still receive a change-log entry and a path/command check.

## Verification

- Check referenced paths and commands against the project.
